# Write the baseline script — you design the test, I execute it

You raised the objection that the CC paper has **no baseline showing its 29-signal panel adds value**. A lexical baseline has since been run and the panel beat it on 6/6 tasks. But that answered the weaker question — *is there a text shortcut?* — not the harder one you actually asked: **does the engineered panel plus its selector beat a simple model?**

⚠️ **The hidden-state probe you asked for is not runnable.** Raw hidden states were never banked; only the engineered panel signals were. That needs a fresh extraction run.

So write the strongest test that **is** runnable on the banked data. You design it; I execute it and report whatever it says, including if it goes against the paper. Do not soften it.

## What is banked

**Per (task, model), an `.npz`:**
```
score_matrix : float64 (n, 27)   the 27 engineered panel signals, already computed
labels       : int64   (n,)      0/1
sample_idx   : int64   (n,)
panel        : JSON list of 27 entries, each [step, family, signal_name]
               families seen: "Attention", plus readout/residual/confidence families
meta         : JSON
```
Example panel entries: `[0,"Attention","final_js"]`, `[0,"Attention","final_bos_mass"]`, `[0,"Attention","final_v_norm_bos"]`.

**Per task, a `.jsonl`** with `prompt`, `label`, `stem_id`. `stem_id` groups paired prompts — the same question shown once with the correct candidate and once with the hallucinated one. **Row order in the jsonl aligns with `sample_idx` order in the npz**; verify this rather than assuming it.

Paths: matrices under `stage_b/profiles_bench/<task>/<model>.profile.json` alongside `<model>.matrix.npz`; also `stage_b/profiles_ext/<task>/`. Data under `stage_b/data_bench/<task>_seed20260711_n1000.jsonl`.

## What the paper does now, which is what you are testing against

For each deployment it runs a **nested out-of-bag bootstrap that re-selects the winning cell and sign-locks inside each resample**, then reports the OOB AUROC median of that procedure. So it picks **one** of 27 signals per deployment, honestly.

Reported panel OOB medians to beat: `triviaqa_paired_rep` 0.9095 · `halueval_qa` 0.8751 · `anli_r1_rep` 0.8410 · `halueval_summarization` 0.7481 · `halueval_dialogue` 0.7564 · `anli_r2` 0.6531.

## Write a script that answers

The core question: **is the select-one-signal machinery justified, or would something simpler do as well or better?** Design the comparators you think actually settle that. Candidates you may use, reject, or improve on:

- a multivariate model on all 27 columns (does using everything beat selecting one?)
- the single best *fixed* column chosen once across models, versus per-deployment selection
- a confidence-only or single-family restriction, to see which family carries it
- whatever else you judge more decisive

**Requirements:**

- 🔒 **Group by `stem_id`** so paired prompts never straddle a split. This is not optional; without it the same question appears on both sides.
- ⚖️ **Make the comparison as like-for-like as you can**, and where it cannot be, say so in the output. The panel figure comes from nested selection; a naive CV number is not directly comparable, and the script should not pretend otherwise.
- 📉 **Report effect sizes and uncertainty**, not just point estimates.
- 🚨 **State in the output what result would mean the panel is NOT justified**, before showing the numbers. Pre-commit the interpretation.
- 🐍 Python 3.9, numpy/pandas/scikit-learn only. Read-only over the data. Print a readable report.
- 📁 Take `--data-dir` and `--profiles-dir` as arguments; hardcode no absolute paths.

Return **only the complete script**, ready to run. No preamble. Put your reasoning in comments and in the report text the script prints.
