## Hard rules for anyone executing

- Model-facing stimulus text stays plain — no emojis, no decoration; every character is tokens.
- Camera test on all shared-event text: counts/timestamps/quotes legal; frequency adverbs and character adjectives banned; evaluations must be generated by agents, not inherited.
- Named needs come from [[needs-inventory]] only. If you can see a visual, it is a strategy, not a need.
- Nothing resolution-shaped in any stimulus, ever — the Rosenberg endpoint (t_sol) must stay unscripted.
- Stakes are sharpened with props (timestamped artifacts), never proclamations or "don't resolve" instructions.
- Matched decoding parameters on both dyad sides, always (temperature asymmetry confounds every magnitude metric).
- Repo↔wiki separation: code lives in a repo, spec lives here; wiki→repo pointers fine, never the reverse.

## Phase 3 — Ceiling-gate pilot · BLOCKED on Phases 1–2 · `[MODEL→USER]`

Purpose: verify the design produces contrast before anything is registered.

1. Small pilot on E3 (order of 10 dialogues per arm, seeds varied).
2. **Ceiling gate:** measure spontaneous-resolution rate in neutral and jackal arms. If they over-resolve (threshold = user decision at gate time), sharpen stakes — props, not proclamations — and re-pilot. This gate exists because LLM agreeableness may dissolve all conflict regardless of arm; without stalemates in the control arms there is no contrast to detect.
3. **Grammar reachability:** confirm giraffe-arm dialogues actually traverse the state machine (REFL loops occur; hearing markers fire; the parser isn't vacuous).
4. `[USER GATE]` **Judge validation:** the user hand-labels a small set (~20–40 turns) for authenticity and t_hear; agreement is reported across **three** independent authenticity opinions — expert hand-label ⟂ blinded judge ⟂ persona-vector projection ([[prior-art-persona-vectors]]) — before the judge is trusted. Persona projection is a noisy co-label (trait entanglement), a cross-check not ground truth. Disagreements feed rubric revision.
5. Output: pilot summary page (results/ is not used — this is calibration, not a finding; a `pilot-notes.md` in this folder).

## Phase 5 — Extensions · BLOCKED on Phase 4 verdict · each `[MODEL→USER]`

Ordered by expected information per unit work; each gets its own prereg or explicit exploratory tag:

1. **Asymmetric arms** (C1/C2 — only one side giraffe): reception vs expression.
2. **Ladder rungs:** cousins (Qwen2.5-7B × Qwen3-8B — pairs a legible instrument with the family's known v3-collapse oddball), then siblings (×32B), strangers (×Llama; the family locus-dissociation predicts possible cross-locus coupling).
3. **Causal / heckler arm — directed-steering primary, noise control** (reworked 2026-07-09, [[prior-art-persona-vectors]]): the primary probe is **directed persona-vector steering** `h_ℓ ← h_ℓ ± α·v_ℓ` — steer a turn *against* the sycophancy vector and test whether a performative turn collapses while a genuinely-navigated turn survives (deep basin); steer *toward* it to see which dialogues amplify vs resist. Titrate α along the coherence budget (their MMLU-vs-α curve) for basin-depth spectroscopy. Isotropic Gaussian noise becomes the **undirected control**, with forward-only curvature (E[KL] ≈ ½σ²·tr(F) against analytic Fisher) as its estimator. Shares harness with candidate #6 (their `h±α·v` is the directed cousin of v_top steering).
4. **Cross-scoring vs hallucination profiles:** strain-vs-content question (AUROC ≈ 0.5 ⇒ distinct strains; high ⇒ one generic strain signal — either outcome is a finding).
5. **Temporal discontinuity analysis:** suppression-plateau→snap vs solution-emergence, with surrogate-series nulls (permuted turn order / AR-matched) — no snap-hunting without a null model.
6. **Guard packaging:** if and only if a deployable authentic-vs-performative profile emerges, wire it as a furnace-guard domain calibration.
