# 📊 Rank, ELI12

**Companion:** [null-space-eli12](260419-null-space-eli12.md) (where rank gets used)

---

## 🎯 The big idea

"Rank" is just **how many top directions we're paying attention to**. It's the dial we turn between *strict* (pay attention to very few) and *generous* (pay attention to a lot).

That's the whole concept. The rest is "why we need a dial" and "what the dial settings mean."

---

## 🏠 The room analogy

The model's thought lives in a giant room with **3000 directions** you could walk. Way too many to track one by one.

So we do this trick:
1. Score every direction by *how much walking that way would change the next word*.
2. Sort them from most-output-changing to least.
3. Pick the top **r**.

That **r** is the rank. 📐

- 🎚️ **Rank 1** = just the single most important direction ("north only")
- 🎚️ **Rank 8** = the top 8 most important directions
- 🎚️ **Rank 64** = the top 64 most important directions
- 🎚️ **Rank 3000** = every direction (no filter — but now it's not helpful anymore)

---

## 🎛️ Why we need a dial

If we set rank too low (rank 1), we're only looking at one direction — we miss real movement.
If we set rank too high (rank 3000), every direction counts, so there's nothing *left over* to measure as "null." 🫥

The good setting is somewhere in the middle: high enough to cover the directions that really matter, low enough that whatever's left over is genuinely *off-topic* movement.

Since we don't know the right setting in advance, **we sweep a few ranks at once** — 8, 16, 32, 64 — and see which one gives the best separation between control and contradiction. 🧪

---

## 🧮 Where rank comes from (the math bit)

We build a matrix that encodes "moving in direction x → changes output by y," weighted by how probable each word is:

```
A = sqrt(p_t) · W_u
```

Then we do an SVD of `A`. SVD hands us back a sorted list of directions — the **right singular vectors** — ordered by importance. The first one is "the single biggest output-changer." The second is "the biggest output-changer perpendicular to the first." And so on.

Rank **r** = keep the first r of those sorted directions. The others get thrown away (or, more precisely: treated as "null").

---

## 🎁 The surprise from our smoke test

When we actually ran this on Llama 3.2 3B, we expected importance to be spread across many directions. It wasn't:

| Rank | Share of total "importance" captured |
|---|---|
| 8 | **99.1%** 😳 |
| 16 | 99.5% |
| 32 | 99.7% |
| 64 | 99.8% |

By rank 8 we've already captured almost all the output-changing power. The other ~2,992 directions? Basically dead knobs. 🔴

This is called **low effective rank** — even though the matrix *technically* has rank ~1000, almost all its "weight" is concentrated in the top handful of directions.

Why it happens: `sqrt(p_t)` squishes down all the words the model is unsure about. If the model is confident (p_t is sharp), only a few words get significant `sqrt(p_t)` weight, so only a few rows of `W_u` contribute. The operator collapses.

---

## ⚠️ Why this matters for v3

1. Our current rank sweep (8, 16, 32, 64) is mostly sampling the *saturated tail* of the spectrum. 
2. The ranks where things actually differ might be **smaller** — rank 1, 2, 4. That's where we'd see the curve rise before flattening out. 📉
3. Next run: probably extend the sweep to include (1, 2, 4) as well as (8, 16, 32, 64). 🔧

---

## 🎯 One-sentence takeaway

> Rank is the number of "most important directions" we keep — a dial we sweep to find the setting where control and contradiction separate cleanest.
