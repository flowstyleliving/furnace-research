# Dead Runs — Falcon-180B, Command A (2026-06-23)

**Status:** `[DEAD]` — two models attempted, both failed. Noted for completeness. No further work planned.

## Falcon-180B (tiiuae/falcon-180B-chat)

**Attempt 1:** OOM on 2× A100 (80GB each). Model at nf4 ≈ 105GB with overhead, exceeds 160GB combined.

**Attempt 2:** Added `llm_int8_enable_fp32_cpu_offload=True` to BitsAndBytesConfig. Still OOM — FP32 module overhead pushes past available VRAM even with CPU offloading.

**Verdict:** Falcon-180B is too large for available Modal GPU configurations. 4× A100 or H100 would be needed. Not worth the cost for a single datapoint.

## Command A (CohereForAI/c4ai-command-a-111B)

**Attempt:** nf4 on 2× A100. Model loads successfully but produces `\n` as first token on 100% of samples.

**Root cause:** Chat template incompatibility. Command A uses a non-standard template that the standard `apply_chat_template` call doesn't handle. The model outputs newlines instead of YES/NO.

**Verdict:** Template engineering required. 0% YES/NO rate means zero usable data. Not worth fixing for a model that would be an outlier at 111B (between 72B and 180B, both already represented or dead).

## Lessons

- **2× A100 ceiling:** Models above \~80GB at nf4 are not viable on the current Modal setup.
- **Template compatibility:** Non-standard chat templates are a hard blocker for automated YES/NO extraction. Pre-flight template check needed before launching runs on unfamiliar model families.
- **Diminishing returns:** With Qwen-72B (deployable), Llama-70B (deployable), and Falcon-180B (dead), the scale axis above 70B is adequately characterized. 111B wouldn't change any conclusion.
